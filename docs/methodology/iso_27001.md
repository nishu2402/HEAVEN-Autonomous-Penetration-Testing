# HEAVEN ↔ ISO/IEC 27001:2022 (Annex A)

Mapping of HEAVEN's detectors against the [ISO/IEC 27001:2022](https://www.iso.org/standard/27001)
Annex A control set (as detailed in ISO/IEC 27002:2022), including
**Amendment 1:2024** (climate-action changes). Annex A groups 93
controls into four themes: **A.5 Organizational**, **A.6 People**,
**A.7 Physical** and **A.8 Technological**.

ISO/IEC 27001 certifies an *Information Security Management System (ISMS)*, a
governance process, so most controls are attested through policy, records and
audit rather than a scan. HEAVEN provides **technical evidence** for every control
with an observable footprint (chiefly under A.8): management of technical
vulnerabilities, secure configuration, network security, cryptography in transit,
monitoring, and application-security testing, each named to a real detector.
People, physical and policy/governance controls have no scan footprint and are
listed as **out-of-band (analyst-attested)**, outside what any external scanner
can evidence, and never fabricated.

A control row is **✓ exercised** on the live Methodology page only when the
HEAVEN detector it names actually produced a finding in the active engagement.

## Coverage summary

| Annex A theme | HEAVEN evidence |
|---|---|
| A.5 Organizational Controls | threat-intel, transit crypto, cloud posture, asset inventory |
| A.6 People Controls | organizational, HR / training, analyst-attested |
| A.7 Physical Controls | physical, analyst-attested |
| A.8 Technological Controls | extensive, HEAVEN's core evidence surface |

## Detailed mapping

### A.5 Organizational Controls
| Control | Description | HEAVEN coverage |
|---|---|---|
| A.5.7 | Threat intelligence | `heaven.recon.adaptive_intel`, passive intel enrichment |
| A.5.9 | Inventory of information and other assets | `heaven.devsecops.inventory`, `heaven.recon.network_scanner` (host/service asset discovery + inventory table) |
| A.5.14 | Information transfer (protected in transit) | `heaven.vulnscan.ssl_scanner` |
| A.5.23 | Information security for use of cloud services | `heaven.recon.cloud_enum`, `heaven.recon.cloud_iam` |

**Out-of-band (analyst-attested):** A.5.1 (policies for information security) is
governed by the ISMS, a documentation control, not a scannable property.

### A.6 People Controls
**Out-of-band (analyst-attested):** all People-theme controls: A.6.3 (awareness,
education & training) and A.6.8 (information-security event reporting), plus
screening, terms of employment, disciplinary process and remote working, are HR/
ISMS controls with no network-observable footprint. HEAVEN never fabricates them.

### A.7 Physical Controls
**Out-of-band (analyst-attested):** all Physical-theme controls: A.7.1 (physical
security perimeters), A.7.10 (storage media), plus secure areas, entry, equipment
siting, cabling and disposal, are site/physical controls outside the reach of a
remote autonomous scanner.

### A.8 Technological Controls
This is HEAVEN's core evidence surface, the technical controls with a
measurable external or credentialed footprint.

| Control | Description | HEAVEN coverage |
|---|---|---|
| A.8.5 | Secure authentication | `heaven.vulnscan.auth_scanner` |
| A.8.8 | Management of technical vulnerabilities | `heaven.vulnscan.cve_mapper`, `heaven.vulnscan.eol_scanner`, `heaven.vulnscan.sca_scanner` |
| A.8.9 | Configuration management | `heaven.recon.web_crawler`, `heaven.vulnscan.dir_fuzzer`, `heaven.recon.network_exposure` |
| A.8.12 | Data leakage prevention | `heaven.vulnscan.exposure_scanner` (exposed secrets / files) |
| A.8.16 | Monitoring activities | `heaven.utils.watcher` (`heaven watch`, recurring re-scan detects new/changed exposure over time) + `heaven.devsecops.alerting` (event delivery) |
| A.8.20 | Networks security | `heaven.recon.network_scanner`, `heaven.recon.network_exposure` |
| A.8.21 | Security of network services | `heaven.recon.network_exposure` (cleartext services), `heaven.vulnscan.ssl_scanner` |
| A.8.22 | Segregation of networks | `heaven.recon.network_scanner` (host-to-host reachability from the scan vantage point evidences segmentation boundaries) |
| A.8.24 | Use of cryptography | `heaven.vulnscan.ssl_scanner`, `heaven.vulnscan.advanced_attacks` (JWT/crypto misuse) |
| A.8.25 | Secure development life cycle | `heaven.vulnscan.sast_runner` |
| A.8.26 | Application security requirements | `heaven.vulnscan.injection_scanner`, `heaven.vulnscan.api_scanner` |
| A.8.28 | Secure coding | `heaven.vulnscan.sast_runner`, `heaven.vulnscan.sca_scanner` |
| A.8.29 | Security testing in development and acceptance | `heaven.orchestrator` (the full vulnscan suite) |

**Out-of-band (analyst-attested):** A.8.7 (protection against malware) is an
endpoint control, and A.8.23 (web filtering) is an egress control, neither has an
external-scan footprint.
